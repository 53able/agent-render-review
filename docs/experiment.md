# 実験手順: ADEユーザーは開発中のページに vork のビジュアルを採用するか

ai-builder-mentor のレビュー（2026-11-07）で提案された7日実験の手順です。結果はまだありません。

## 問い

1. ADEユーザーは、自作アプリ用のビジュアルを繰り返し必要としているか。
2. その仕事に、形状・構図・物体を保つ3Dの制御が必要か。
3. Director を開く手間以上に、比較と修正が楽になるか。

## 対象と課題

- 対象: ADE（Claude Code、Codex など）でWebアプリを作っており、今ちょうどキービジュアルを必要としている3人。
- 課題: 開発中のページ1つに、採用できるビジュアルを1枚組み込む。
- 利用の契機: ページの実装中に素材が必要になった時点。こちらから課題を作らない。

## 準備（参加者ごと）

1. vork と vork Director を導入する（README の「ADEモード」）。
2. 参加者のプロジェクトで MCP を登録する。
3. `.vork/config.json` に `pageUrl` と `assetUrlPattern` を書く（開発サーバーのURL、ヒーロー画像のパス）。
4. 観察者は画面共有で見るだけにし、操作の説明は最初の5分に限る。

## 計測

`node server.mts --report <project>` で自動集計できるもの:

| 指標 | 内容 |
|---|---|
| minutesFirstProposalToAdoption | 最初の提案から採用までの分数 |
| feedbackRounds | Director から送ったフィードバックの回数 |
| proposals / discards | 提案数と破棄数 |
| adoptions / adoptionRejections | 採用数と採用依頼の却下数 |

観察で記録するもの:

- 文脈の再説明回数（ADEでの依頼内容を Director 側でもう一度書いた回数）
- 手作業の受け渡し回数（画像のコピー、パスの書き換えなど）
- 採用後にページのコードが採用画像を参照したか
- 次の制作機会に自発的に使ったか（1週間後に確認）

## 成功・変更・中止の基準（案）

- 成功: 3人中2人が実際のページに採用し、少なくとも1人が別の制作機会でも自発的に使う。
- 対象を変える: 素材の需要がない。
- vork への固執をやめる: 需要はあるが、3Dの制御が不要（2D画像生成で足りる）。
- ADE連携を優先して直す: 需要も3Dの必要もあるが、受け渡しや待機が障害になっている。

## 記録の扱い

- `.vork/state.json` にはシーンと依頼文が残る。参加者の同意なく持ち出さない。
- 集計値と観察メモだけを共有する。
